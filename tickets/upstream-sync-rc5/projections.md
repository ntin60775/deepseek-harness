## Находки и вердикты триажа

Нумерация: C — proj-coverage, A — proj-audit, M — proj-merge, G — proj-guides, E — proj-evidence.

1. **C1/A1/M3 — «960 файлов» не та метрика.** Подтверждена лично: аудит печатает `overlap.length` ([scripts/fork-upgrade-audit.ts:327-343](../../scripts/fork-upgrade-audit.ts)), а 960 — `git diff --name-only` по диапазону. Сегодняшнее совпадение 5818 доказывает, что спека читала две разные команды. Правка: «коммитов 238 (мерджей 99), upstream изменил 960 файлов, пересечение 61, гайдов 3 новых + 1 изменённый».
2. **C2/M1 — конфликтов семь, а не шесть.** Подтверждена: `packages/client/ui-subagent/README.i18n.yaml` был в первом же прогоне `git merge-tree`, спека его потеряла. Правка: седьмой путь в п.3, «точный список считает ритуал на прогоне».
3. **M2 — pre-commit pairing-хук уронит merge-коммит.** Подтверждена: `lefthook.yml` держит job «translation pairing (staged records)» на glob `*.i18n.yaml` с `verify-translation-pairing --cached`; после `--theirs` хеш записи не совпадёт с байтами разрешённого `README.md`. Ритуал перезаписывает пары только в docs-фазе, то есть уже после коммита. Правка: перезапись пар до `git commit` — в ритуале и в спеке.
4. **A3 — после мержа аудит пуст, а ритуал гоняет его после мержа.** Подтверждена: `merge-base HEAD target` после мержа равен самому target, ветка «влит полностью» печатает нули, и список гайдов исчезает ровно в том прогоне, ради которого аудит существует. Правка: снять `MERGE_BASE` до мержа и передать `--base` после; в спеке — кейс post-merge.
5. **A4/C3 — правка аудита без рефакторинга недоказуема.** Подтверждена: у `scripts/fork-upgrade-audit.ts` нет экспортов, `argv`/`process.exit` на верхнем уровне, `ROOT` прибит к каталогу скрипта; спек, гоняющая живой репозиторий с плавающими числами, не падает на неверной реализации. Правка: вынести `renderAudit(args, root)` по образцу [scripts/change-scope.ts:233-244](../../scripts/change-scope.ts), кейсы — из списка A10.
6. **A2 — исключение «тег впереди → оставить тег» скрывает невлитое.** Подтверждена лично: `dsh-v0.2.2-rc.5` — параллельная релизная линия, её гайд `web-search-deepseek-model-default` есть только в ней; диапазон от rc.5 к master даёт 1640 коммитов мусора. Правка: база всегда `merge-base`, тег — только провенанс в шапке, громкое предупреждение, если тег не влит в HEAD.
7. **A5 — `merge-base --is-ancestor` трёхзначен, `execFileSync` бросает на 1.** Подтверждена. Правка: `spawnSync` + разбор 0/1/128 в кейсах спек.
8. **A6 — `--record-base` становится отравляемым.** Подтверждена: до мержа он пишет `dsh-v0.2.2-rc.5`, которого нет в HEAD, и следующий аудит скрывает ровно этот диапазон. Правка: предупреждение при теге вне HEAD; файл объявляется провенансом, а не источником диапазона.
9. **C4/E5 — свежесть каталогов нечем подтвердить в заявленном контуре.** Подтверждена: `verify-client-catalog` не имеет `quick: true` ([scripts/run-gates.ts:872](../../scripts/run-gates.ts)), поэтому `test:docs` его не гоняет. Правка: носитель — `pnpm run verify-client-catalog` (или `doc-sync`), и это входит в п.6.
10. **C5 — sha из вывода аудита нельзя класть в трекемый отчёт.** Подтверждена: `tickets/` трекается, `verify-repository-references` ловит любой id с hex-буквой в локальной базе. Правка: в отчёт — тег и числа, sha только в консоли.
11. **C6/E1 — `test:gui:changed` не является доказательством мержа.** Подтверждена лично: на чистом дереве селектор даёт «0 tests selected» и exit 0; после merge-коммита дерево чистое по определению ритуала. Правка: убрать из носителей; GUI-доказательства — focused-список.
12. **C7 — п.8 не называет носители, которые протокол форка обязывает править в том же коммите.** Подтверждена: [docs/reference/fork-merge-ritual.md:56](../../docs/reference/fork-merge-ritual.md) требует правки `GENERATED_CONFLICTS`, этой страницы и Agent Note; [packages/fork/README.md:35](../../packages/fork/README.md) описывает старый диапазон. Правка: добавить оба носителя в п.8.
13. **C8/E2 — focused-список не покрывает половину затронутых пакетов.** Подтверждена: в дельте `ui-sidebar-documentpreview` (27 файлов), `ui-deliverables` (14), `shortcuts` (14), `ui-account-notifications` (13), `connection` (13), `ui-settings-models` (12), плюс `session-persistence-sqlite` и `sandbox-policy`, где апстрим менял транзакции и переименовывал пакет. Правка: расширить focused и назвать unit-лэйн в пробеле.
14. **E3 — страница ревью forge не покрыта ни одним носителем.** Подтверждена: `packages/experimental/client-ui-forge` вне `GUI_SCOPE` селектора и вне списка п.5. Спорное → оператору: добавить экран в живую пробу или записать явный пробел.
15. **E4 — replay-лэйн `test:web` отсутствует и не назван.** Подтверждена: [docs/reference/fork-gui-test-loop.md:40](../../docs/reference/fork-gui-test-loop.md) требует focused replay для видимых изменений; спека заменяет его живой пробой, но этого не пишет. Правка: строка в «Ограничения».
16. **E6 — пин Node 24 живёт только в ритуале.** Подтверждена: `engines` не проверяется, `vitest.snapshot.config.ts` версию не читает; на Node 22 падают PTC-сценарии. Правка: `node -v` в отчёте перед `test:snapshot`.
17. **E7 — «классификатор без ERROR» не совпадает со словарём скрипта.** Подтверждена: категории `ERROR` нет, есть `MISSING`, `NEW` и строка `classify: FAILED`, exit 1. Правка: критерий — «exit code 0».
18. **E8 — grep-критерии вакуозелены при крахе носителя.** Подтверждена: `--dump-config-schema` с ненулевым выходом не содержит `invalid config:` и печатает «сообщает о других находках»; то же с `failed to load`. Правка: критерий привязывается к exit code.
19. **C9/M4 — «~30 влитых гайдов» неверно.** Подтверждена: от тега 44 строки, из них к делу 4; от merge-base 3 A + 1 M. Правка числа.
20. **C10 — «162+ коммита» устарело.** Подтверждена: `upstream/master..HEAD` = 168. Правка: 168 или без числа.
21. **C11/M5 — bookkeeping юнита не назван в носителях.** Подтверждена: спека, строка индекса `docs/plans/README.md` и исключение в `scripts/translation-pairing.manifest.json` лежат незакоммиченными и сами красят preflight. Правка: коммит до мержа.
22. **M7 — сдвиг слота для внешнего плагина всплывает в audit `--strict`.** Подтверждена как факт: `conversation.composer.dock` проверяется через `git grep` по владельцам; MISSING останавливает прогон до записи базы. Отдельной правки не требует, но отчёт тикета должен это назвать.
23. **A7 — запрет sha в базе подтверждён с оговорками.** Гейт ловит только id из локальной базы объектов; любой закоммиченный пример вывода с реальным sha краснит `test:docs`. Учтено в п.10.

24. **G1 — строки `- id: web` в профиле `web` нет.** Подтверждена: `grep` по `/home/prog7/.dsh/profiles/web/cordis.patch.yml` пуст. Правка: пин добавляется НОВЫМ top-level элементом `- id: web` с `name` и полным `config`; `insert:` с этим id даёт предупреждение и пропуск, `insert:` без patch-id — дубль строки.
25. **G2 — `config` строки заменяется целиком.** Подтверждена: без `fetchProvider: http` ключ исчезнет, а после мержа в базе остаётся только `fetchProvider`, при двух usable fetch-провайдерах это `WEB_PROVIDER_AMBIGUOUS`. Правка: в пине оба ключа, доказательство — `--dump-config` под слоем профиля.
26. **G3 — `--dump-config-schema` не доказывает применение.** Подтверждена: команда печатает схему, значения конфига в `x-cordis.entries` не входят, ненайденный target — только warning; сейчас она вообще exit=1 с «unrecognized Loader tree carrier». Правка: носитель — `pnpm dsh --profile web --dump-config` с обоими ключами и меткой слоя, отсутствие `patch:`-предупреждения, страница Settings.
27. **G4 — «профили стоят на `danger-full-access`» неверно для `headless` и `sdk`.** Подтверждена: пресеты с `defaultPreset: danger-full-access` есть только в `web`; `headless`/`sdk` держат пустой список и получают `workspace-write` с approval из base. Правка: в п.4 назвать `sdk` (SDK `setWorkingDirectory`) и `headless` как реальные носители риска гайда, грант `.git` нужен там уже сейчас.
28. **G5 — у гайда по песочнице есть готовые исполняемые носители.** Подтверждена: `packages/sandbox/sandbox-policy/tests/workspace-root.spec.ts` и `packages/experimental/worktree/tests/sandbox.spec.ts` (запись в `.git` denied → грант → commit ok). Правка: оба файла в focused-прогон п.5, с проверкой, что worktree-тест не skip.
29. **G7 — живую пробу нельзя поднять копией `package.json`.** Подтверждена: bundle резолвится через `node_modules` профиля, runtime линки не создаёт; `DSH_HOME` копии должен быть той же глубины, что `~/.dsh`, иначе относительные симлинки `link:` ломаются. Правка: в п.7 назвать копируемые файлы (`package.json`, `cordis.yml`, `cordis.patch.yml`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `node_modules`), глубину `DSH_HOME`, признак `skipping profile bundle` как провал.
30. **G8 — правка профиля дёргает HMR основного хоста.** Подтверждена: `patchReload: live` применяет патч на `:3080` сразу. Правка: пин сначала проверяется overlay'ем/копией, затем пишется в профиль; критерий «лог без `failed to load`» заменяется на exit code и серверный лог старта.
31. **G9 — пина в git нет, он не ревьюится.** Правка: точные строки патча и фрагмент `--dump-config` кладутся в отчёт тикета.
32. **G10 — на маршруте `qwen-token-plan-deepseek` пин ничего не меняет.** Подтверждена: апстрим и без пина выбирает `deepseek-search-api` для не-deepseek-маршрутов; поведение и оплата меняются только на `deepseek-official`/`deepseek-account`. Правка: в п.4 сказать, на каких маршрутах пин реально держит поведение.
33. **G11 — `--dump-config-schema` при exit=1 дописывает `[ELIFECYCLE]` в stdout.** Учтено в п.26: JSON парсится до этой строки, критерий — exit code.
34. **E2/M2 — ритуал без правки упадёт на merge-коммите.** Сведено с п.3: перезапись пар до коммита — часть мержа, а не docs-фазы.

Отвергнутых находок нет: все 34 подтверждены фактами репозитория. Оверинжиниринг срезан в одной: полный список из 13 кейсов спек аудита (A10) принят как ориентир, но в тикет войдут семь, которые валят отдельные неверные реализации; кейс detached HEAD и property-проверка «base в HEAD» — по одной строке каждый.

## Спорное, ушедшее оператору

- Пункт 14 (страница ревью forge). Решение оператора 2026-11-19: экран страницы ревью проверяется в живой пробе на `:3081`; forge остаётся вне обоих контуров тестов, это названо пробелом.
- Механизм лайт-контура. Решение оператора 2026-11-19: флаг `FORK_SKIP_FULL_GUI=1` в ритуале пропускает полный `test:gui` с названной подменой; ручные фазы и полный прогон отклонены.
- Правка спеки по находкам 1–34. Решение оператора 2026-11-19: принять все 34; спека переписана, правки перечислены в её разделах «Готово» 1–8 и «Ограничения».
