Запись гейта: прогон состоялся 2026-11-11, спека [docs/plans/transcript-readability.md](../../docs/plans/transcript-readability.md) (утверждена на план-гейте 2026-11-11, status: active). ## Находки и вердикты триажа

Обозначения: C — critic-coverage, P — critic-proof, O — critic-order, R — critic-risk.

### Подтверждены — правки спеки (механические и выводимые из канона)

1. **Предикат карточки финала (C1 + O4).** `data.finalNode` есть у каждой settled-реплики ([assistant.ts:268-292](../../packages/client/ui-chat/src/client/conversation-nodes/assistant.ts)), буквальное правило спеки пометило бы промежуточные реплики. Предикат через `turnProcess` не работает в Verbose (`foldCompletedTurns: false`). Робастный предикат уже существует в [AssistantNodeView.tsx:31-35](../../packages/client/ui-chat/src/client/chat/AssistantNodeView.tsx): `turn.status === 'closed'` + `tail.closing.finalNode.seq === data.finalNode.seq`. Правка: назвать этот предикат; только response-место (`groupPart !== 'reasoning'`); карточка только при `turn/end.reason === 'completed'`; края без карточки: открытый ход, нет closing text-реплики, image-only финал, stopped/failed/interrupted/max-tokens. Предикат не зависит от режима и партиального хвоста. Разногласие срезов (C предлагал answerStep, O показал Verbose-край) разрешено в пользу O证据 кода.
2. **Подпись карточки (C4 + P4 + O5 + R2).** `settings.foldedReplies.final` = «Final answer only» / «Только окончательный ответ» во всех 8 словарях — ярлык настройки, не подпись. Правка: новый ключ (например `message.finalAnswer`) во всех 8 словарях ui-chat; ключ настроек в транскрипте не потребляется, термин согласован. Прогресс-бар `aria-hidden` — новые ключи ui-conversation не нужны.
3. **Крепление оболочки и motion-контракт (O1 + O2 + R1).** Условный монтаж оболочки ломает стабильное поддерево группы ([ChatGroupSeat.tsx:1](../../packages/client/ui-chat/src/client/chat/ChatGroupSeat.tsx), README ui-chat:116,124,132), disclosure-состояния, якоря позиции и fold-батчи. Правка: оболочка — всегда смонтированный presentational div без роли/aria-label, без overflow/contain/transform; переключение раскрытия меняет только материал классом, не монтаж; носитель переформулирован как «материал оболочки по режимам и состояниям» + критерии «участники не перемонтируются, disclosure и якорь сохраняются, высота заголовка не скачет под fold-часами». Геометрическая развилка (тело-only vs заголовок+тело) вынесена оператору (спорное №1).
4. **Канал и интервал дока (C3 + O3).** Доступный канал — `session.running` в owner-пропсах `InputZone.session` ([contract/slots.ts:449-452](../../packages/client/ui-conversation/src/client/contract/slots.ts)); точная граница хода клиенту не дана (`turnBoundary` host-only), queued-ввод переживает границу хода без смены `running`. Правка: триггер — состояние (непустая проекция + running), а не только событие изменения; ручное сворачивание подавляет авто-раскрытие до конца интервала. Интервал (сессия vs ход) вынесен оператору (спорное №2).
5. **Терминология (C5 + C6).** «Сегмент процесса» → «группа процесса» (канонический термин; «segment» занят group-tree/exchange-сегментами). «trigger-notice» → «turn-trigger notice» (kind `turn-trigger`, [message.ts:142](../../packages/client/ui-chat/src/client/conversation-nodes/message.ts)).
6. **Заголовки по состояниям (C2).** Наличие заголовка зависит от состояния, не только режима: Detailed running и Detailed latest completed при On next message — headerless. Правка: формулировать по фактическому заголовку (Compact/Standard оба состояния, Detailed historical — титульная строка; Verbose/Detailed running/отложенный — без титульной строки); охват уточнён как «видимое тело группы».
7. **Демо-путь (C7 + P3).** Replay — e2e-полоса, не страница GUI; в subagent-conversation нет `todo_write`, «во время работы» там ненаблюдаемо. Правка: демо — живая многоагентная сессия через dev:web; носитель дока на идущем ходе — сценарий queue-actions ([layout.expected.md:18-21](../../snapshots/web/queue-actions/layout.expected.md), фикстура дописывает todo/write в живом ходе).
8. **Пустой критерий tool-details (P2).** Снимок tool-details захватывает только карточки инструментов ([tool-details.e2e.ts:79-82](../../apps/web/tests/tool-details.e2e.ts)), CSS-оболочка и подпись финала вне захвата. Правка: tool-details — охранник неизменности карточек; сценарии с областью транскрипта — collapse-timing (`[data-chat-flow]`), deepseek-messages-chat (centerCol), subagent-conversation.
9. **Цена test:web и итерация (P5).** `test:web` = полная сборка + сериальная браузерная сюита. Правка: дешёвая итерация — `build:artifacts` + `test:web:built` с фильтром сценария; полный `test:web` — финальный гейт; порядок detect → refresh → повторный зелёный прогон.
10. **Масштаб snapshot-churn и механический критерий диффа (R4).** Замер среза: ≳40 сценариев, ~93 expected-файла в snapshots/web и ~106 в apps/web/tests/expected содержат реплики; подпись финала попадает в каждый закрытый ход. Правка: назвать измеренный масштаб; механический критерий — в diff expected допустима только новая строка подписи (плюс строки прогресс-полосы в queue-actions/layout.expected.md); любой иной diff блокирует refresh; оболочка без роли/label не попадает в ARIA-снимок.
11. **Семейство и радиус карточки финала (R3 + дизайн-замечание O).** `bg-base` в тёмной теме совпадает с фоном страницы — разделение только штрихом; роль «independent content card» = R20 `--dsw-radius-xl` ([ui-radius.md:36](../../docs/ui-radius.md)); ближайшая приподнятая семья — QuestionComposer/PlanReviewPanel: `--dsw-specific-input-major` + `--dsw-radius-xl` + elevation-panel + border:0. Правка: карточка приводится к этой семье; в критерии добавлено сравнение с соседними поверхностями в обеих темах.
12. **Рёбра нарезки (O6).** Оба UI-пункта пишут одни replay-expected; locale-ключ и карточка — один тикет. Правка: каждый UI-тикет обновляет только свои компонентные спеки; replay-refresh — отдельный блокирующий тикет после обоих UI-пунктов.
13. **Упрощение полосы дока (оверинжиниринг всех срезов).** Прогресс-бар принят оператором в раунде 1 («полосу с прогрессом» в тексте выбранного варианта) — остаётся. Цветные StateDot-счётчики в полосе — третье кодирование тех же чисел, сверх принятого — убраны: полоса = прогресс-бар (aria-hidden) + существующие текстовые счётчики `todo.progress.*`; StateDot остаётся на раскрытых строках.
14. **Вложенные поверхности одного токена (дизайн-замечание O).** Контейнер и вложенные код-блоки/ioCard делят токен `markdown-code-block` — заливка вложенных карточек не контрастирует, но их hairline-контуры сохраняются. Принято как риск; живая проба контуров и контраста уже названа критерием, добавлена одной строкой в Ограничения.
15. **Дизайн-ревью в форке (замечание R).** Обязательность исполнима через fallback скилла dsh-client-ui-ux «When no approver holds that role» — приёмка оператором; ссылка добавлена в п.5.

### Отвергнуты

1. **P1: «model-retry — член группы, исключение противоречиво».** Отвергнута: `groupTree: 'process'` делает retry независимым корнем-сепаратором, не членом — [process-groups.ts:153-155](../../packages/client/ui-chat/src/client/conversation-nodes/process-groups.ts) флашит группу и эмитит узел отдельно; канон ([conversation-nodes README, process grouping](../../packages/client/ui-chat/src/client/conversation-nodes/README.md)) прямо называет model-retry независимым корнем. Исключение в спеке верно по эффекту; уточнено, что retry разрезает контейнер надвое. Терминологическая правка C6 применена отдельно.
2. **Оверинжиниринг «убрать прогресс-бар» (C, P, O).** Отвергнута: бар входил в текст выбранного оператором варианта раунда 1 («по завершении сворачивается в полосу с прогрессом»). Упрощение счётчиков — п.13 выше.
3. **Оверинжиниринг «две новые поверхности — слабое доказательство» (P).** Отмечено как принятый риск: геометрия двойных кромок проверяется живой пробой (названный носитель), структурно финальная карточка не вложена в контейнер (response — независимый корень), соседние контейнеры не возникают (реплика разделяет группы). Подтверждено срезом R.

## Спорное, ушедшее оператору

1. **Крепление оболочки:** контейнер только вокруг тела группы (заголовок — plain-строка над ним; сохраняет ось, высоту строки заголовка и approved «свёрнутая группа — plain») против контейнера вокруг заголовка+тела с постоянной геометрией (свёрнутая группа — тихий чип). Рекомендация: тело-only. **Решение оператора 2026-11-11: тело группы, заголовок сверху.**
2. **Интервал дока:** сессия (`session.running`, доступный канал, «во время работы», без мигания между queued-ходами) против точной границы хода (новый host-канал/проекция, расширение рамок). Рекомендация: сессия. **Решение оператора 2026-11-11: сессия, пока агент работает.**
3. **Пакет правок:** применить все подтверждённые правки 1–15 к спеке решением оператора (правки после план-гейта — только решением оператора). **Решение оператора 2026-11-11: применить все правки.**

Правки применены к спеке 2026-11-11 решением оператора; спека остаётся утверждённой (status: active).

## Границы без находок (сводно по срезам)

Материалы контейнера легальны (0.5px border-l1 + фон без elevation; охранники elevation-styles/radius-styles существуют); токены определены в обеих темах; группировка/режимы/scroll ownership спекой не переопределяются; карточка финала структурно независима от контейнера и не попадает в его scrollport; пагинация без turn/start не блокирует карточку; авто-раскрытие дока не требует нового scroll-кода (рост composer компенсируется существующим механизмом); «зебра» из контейнеров структурно ограничена (реплика разделяет группы); команды test:gui/test:web/test:docs и bundle существуют; компонентные спеки режимов имеют прецедент (chat-view.client.spec.tsx крутит transcriptView/collapseTiming/foldedReplies); контраст-критерий честен как ручной; локальные ссылки спеки разрешаются.
