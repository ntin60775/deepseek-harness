# Политика тестового контура для разработки плагинов и UI-фич

## Цель

Цикл «правка → проверка» при разработке плагинов и UI-фич занимает секунды-минуты и не занимает все ядра: полный `test:gui` (817 spec-файлов, [package.json:88](../../package.json)) исключён из dev-loop, локальные vitest-прогоны по умолчанию получают половину ядер под сохранённым memory-cap 48, канонический inner loop закреплён политикой, одной новой командой и правкой мандата в [packages/client/AGENTS.md](../../packages/client/AGENTS.md). Решения оператора 2026-11-18 (план-гейт): объём «политика + смена дефолтов репо», бюджет `available / 2`, набор «watch в политике + test:gui:changed», носитель «форк-локальный док + AGENTS.md», полный замер test:gui до/после срезан. Решения оператора 2026-11-18 (триаж проекций): формула `min(available/2, 48)` с сохранением memory-cap, zh-pairing development.md через явный вызов dsh-translate-docs, пакетный scope враппера при удалениях, починка предсуществующей битой ссылки gitmark I4. Решение оператора 2026-11-18 (расширение): gate-бюджет и приоритет локальных тяжёлых прогонов с учётом параллельных сессий (пункт 8).

## Готово

1. **Бюджет воркеров.** Локальный (не-CI) бюджет vitest = `max(1, min(floor(available / 2), 48))`; CI (`CI=true`) unchanged; явные override (`--maxWorkers`, `DSH_COVERAGE_MAX_WORKERS`, lane-бюджеты) сохраняют приоритет. Реализация: helper в [scripts/parallelism.ts](../../scripts/parallelism.ts), `LOCAL_TEST_PARALLELISM_CAP=48` остаётся memory-cap поверх половинного бюджета; потребители [vitest.config.ts:169](../../vitest.config.ts) и [run-gates.ts:236](../../scripts/run-gates.ts). Носители: [parallelism.spec.ts](../../scripts/parallelism.spec.ts) — кейсы 12→6, 1→1, 3→1, 256→48 (cap), CI=true→available; новый кейс [run-gates.spec.ts](../../scripts/run-gates.spec.ts) (16 CPU без CI и без override: `DSH_COVERAGE_MAX_WORKERS` '8', partitions 6) — существующие кейсы при cap 48 остаются зелёными (256→48, override '6' читается напрямую и перебивает testBudget, [run-gates.ts:248](../../scripts/run-gates.ts)); ассерт applied-бюджета корневого конфига в [lane-test-budget.spec.ts](../../scripts/lane-test-budget.spec.ts) через runtime-зонд в дочернем процессе (статический импорт конфига ломает composite typecheck; решение оператора 2026-11-18 по триажу ревью-панели тикета 01). Base-proof: halving-кейсы красны на базе (12 CPU сегодня даёт 12, не 6; 16 CPU даёт 16, не 8); приоритет override запинен существующими зелёными кейсами run-gates.spec.ts и CLI-семантикой vitest, отдельный пустой кейс на helper не пишется.
2. **Команда `test:gui:changed`.** Скрипт `scripts/run-gui-changed.ts` (tsx) + строка в package.json. Выборка: tracked-изменения `git diff HEAD` (включает staged) + untracked `src/**/*.{ts,tsx}` без `*.d.ts` + untracked `tests/**/*.{spec,test}.{ts,tsx}`, scope `packages/client` + `packages/host`. Правило удалений: есть удалённый путь в пакете → полный spec-scope этого пакета (`vitest run <pkg>`), иначе `vitest related <существующие файлы> --run`; related молча игнорирует несуществующие пути и принудительно ставит passWithNoTests (эмпирика 2026-11-18), поэтому удаления не передаются в related. Изменённые файлы есть, related-тестов ноль → явное предупреждение с перечислением слепых зон related (config, dynamic loading, subprocesses, built artifacts) и выбором owning-тестов вручную; пустой diff → «0 tests selected», exit 0; файлы вне scope печатаются числом. Голый `vitest --changed` не используется: спайк 2026-11-18 показал, что он игнорирует path-фильтр и шумит от untracked build-артефактов. Носители: спека скрипта на fixture git-репозитории (tracked-правка, untracked-новый src, untracked-новая спека, удаление → пакетный scope, пустой diff, правка вне scope, `.d.ts` отсечён, «изменён, related ноль» предупреждение), живая проба на реальной правке client-пакета; base-proof — команды на базе нет.
3. **Док политики.** `docs/reference/fork-gui-test-loop.md` (English-only, запись в `excluded` [translation-pairing.manifest.json](../../scripts/translation-pairing.manifest.json), ссылка из [docs/reference/README.md](../reference/README.md)): inner loop человека в терминале — явный `pnpm exec vitest watch packages/client/<pkg>` (vitest 4 не включает watch в не-TTY, дефолт `!isCI && stdin.isTTY && !isAgent`); агент/не-TTY — one-shot focused-файл/`-t` или `test:gui:changed`; визуальная проверка через живой dev:web HMR по [dsh-client-ui-ux](../../.agents/skills/dsh-client-ui-ux/SKILL.md); локальные assembled-output лейны обязательны для visible-output правок (focused `DSH_SNAPSHOT=replay test:web`, keyless snapshot по [testing.md](../testing.md)) — «CI owns exhaustive» не отменяет локальную лейну; pre-push — [dsh-pre-push-checks](../../.agents/skills/dsh-pre-push-checks/SKILL.md); полный `test:gui` — только явный запрос (включая критерии ship-тикета/спеки), диагностика CI или необъятный cross-cutting diff. Носители: `doc-sync`, запись exclusion в манифесте (`verify-translation-pairing --list`), `gitmark lint --strict`.
4. **Ladder в packages/client/AGENTS.md.** Ступень 1 «Every GUI code change — pnpm run test:gui … This is the inner loop» ([client/AGENTS.md:151](../../packages/client/AGENTS.md)) заменяется на focused/watch/changed по доку политики; термин «inner loop» переопределяется; ступени 2 (test:web) и 3 (pre-push) сохраняются; строка про красный test:gui на чужом коде адаптируется. Носители: `doc-sync`, вычитка прозы; бюджетного потолка у файла нет.
5. **Строка в корневом AGENTS.md.** Ссылка на док политики вшивается в существующую строку «Never default to the full suite…» ([AGENTS.md:120](../../AGENTS.md)) без прироста слов: бюджет 2080/2080, headroom 0, новая строка гарантированно краснит гейт. Носители: `verify-doc-budgets`, `doc-sync`.
6. **Правдивость development.md и ноты.** Строка «12 for gate schedulers … and 48 for Vitest forks and local coverage» ([development.md:156](../../docs/development.md)) описывает обе формулы: gate/build/typecheck/lint `max(1, min(floor(available/2), 12))` и vitest `max(1, min(floor(available/2), 48))`, плюс приоритет nice 19 и `DSH_LOCAL_PRIORITY` в перечне override'ов; zh-пара обновляется routine-путём i18n-контракта (рабочая сессия обновляет пару сама, [i18n README](../i18n/README.md)); расширенный скилл `dsh-translate-docs` — только явным вызовом оператора, разрешение оператора на zh-pairing получено 2026-11-18; активная нота [2026-10-12-local-gate-speedups.md](../../.agents/notes/implemented/process/2026-10-12-local-gate-speedups.md) (строки про cap 12 и 48) обновляется: оба cap остаются поверх половинного бюджета, измеренный guard не отменяется; строка юнита в [docs/plans/README.md](../plans/README.md) упоминает gate-половину. Носители: `doc-sync` включая `verify-translation-pairing`, `gitmark lint --strict`.
7. **KB-сопровождение.** После записи доков: `gitmark index`, `gitmark lint --strict`, `gitmark map -o docs-map.html`. Предсуществующий красный I4 (битая ссылка в [tickets/subagent-route-visibility/04](../../tickets/subagent-route-visibility/04-panel-width-two-line-route.md)) починен 2026-11-18: `.module.css` → `SubagentCatalog.module.css` (реальный владелец стилей, импорт в SubagentHeaderLineage.tsx). Носители: вывод команд без ошибок.
8. **Gate-бюджет и приоритет локальных тяжёлых прогонов (multi-session).** Локальный бюджет gate-планировщика/build/typecheck/Oxlint/publint = `max(1, min(floor(available/2), LOCAL_PARALLELISM_CAP=12))` вместо `min(available, 12)`; CI unchanged. Локальные тяжёлые entrypoints (`run-gates`, `build`, корневой `vitest.config.ts`) lowering приоритет процесса до nice 19 через `os.setPriority` (наследуется детьми), env `DSH_LOCAL_PRIORITY` задаёт 0–19 (0 = opt-out), невалидное значение падает громко; CI не трогает приоритет. N параллельных сессий делят CPU через планировщик ОС, интерактивная работа вытесняет тяжёлые лейны. Прямые запуски отдельных `verify-*` скриптов приоритет не наследуют от агрегата — граница названа в доке политики (агрегаты или nice-обёртка). Носители: кейсы [parallelism.spec.ts](../../scripts/parallelism.spec.ts) (gate-бюджет 12→6, 256→12, 1→1, CI unchanged) и child-process проба приоритета (дефолт 19, opt-out 0, CI не тронут, невалидный env падает); ко-обновление затронутых кейсов [run-gates.spec.ts](../../scripts/run-gates.spec.ts) и [parallelism.spec.ts](../../scripts/parallelism.spec.ts) с названной причиной; живая проба `getPriority` после запуска агрегата. Base-proof: halving-кейсы и проба приоритета красны на базе. Решение оператора 2026-11-18: «расширь, нужно учитывать что могут работать несколько сессий одновременно», механизм «nice 19 дефолт + половинный gate-бюджет».

## Рамки

- Бюджеты CI и lane-конфигов не меняются: e2e (`DSH_E2E_MAX_WORKERS`), expected (`min(5, available)`), snapshot (env-driven), web (`fileParallelism: false`), bench (2); `LOCAL_PARALLELISM_CAP=12` остаётся cap gate-бюджета поверх половинной формулы (пункт 8).
- Новый скилл не создаётся: политику видят все сессии через строку в AGENTS.md и ladder в client/AGENTS.md.
- Upgrade guide не нужен: локальный бюджет воркеров и dev-команда не входят в публичные поверхности (CLI, профили, settings, persisted data, SDK, wire).
- `docs/testing.md` (1344/1350 слов, парный) не редактируется; zh-pairing затрагивается только для development.md через явный вызов оператора.
- Пустая выборка и предупреждение «related ноль» у `test:gui:changed` — сигналы dev-loop, не доказательство для push; правила dsh-pre-push-checks не меняются.

## Ограничения

- Полный замер `test:gui` до/после не выполняется (решение оператора): бюджет доказывается спеками и focused-замерами, полная лейна остаётся за CI.
- Одно правило выбора на поведение: без fallback-режимов и запасных путей; правило удалений детерминированное (пакетный scope), не деградация.
- Явные override бюджета обязаны продолжать работать; существующие зелёные кейсы run-gates.spec.ts пинят приоритет.
- Приоритет и gate-бюджет пункта 8 не трогают CI; `DSH_LOCAL_PRIORITY` валидируется (0–19), невалидное значение падает громко при старте.
- Доказательства не повторяются: зелёный focused-прогон не перезапускается ради коммита.
- Правки спеки после план-гейта — только решением оператора; настоящий раздел включает решения триажа 2026-11-18.

- dev:web с HMR запущен из этого checkout (процесс `apps/cli/src/bin.ts web`, порт 3080): визуальная итерация без тестов доступна.
