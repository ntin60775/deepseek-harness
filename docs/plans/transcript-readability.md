# Читаемый транскрипт — контейнер процесса, карточка финала, живой список дел

## Цель

Поток чата в режимах с видимым процессом сейчас — стена: строки инструментов, промежуточные реплики и финальный ответ имеют почти один визуальный вес, а список дел свёрнут в тихую полосу. Цель — разделить три слоя восприятия: машинная работа читается как блоки работы, речь агента — как текст на чистом фоне, финальный ответ — как оформленный результат; список дел виден во время работы. Решения приняты оператором сессии: раунды 1–2 план-гейта 2026-11-11 (контейнер группы; подложка + hairline-рамка; карточка финала с подписью при закрытии хода; TodoDock раскрыт во время работы; охват — везде, где виден процесс; доказательства — существующие replay-сценарии, спеки, живая проба) и раунд гейта проекций 2026-11-11 (оболочка вокруг тела группы, заголовок сверху; интервал дока — сессия; пакет правок по отчёту [projections.md](../../tickets/transcript-readability/projections.md) применён полностью).

## Готово

Носители, по которым принимается работа:

1. **Контейнер группы процесса.** Видимое тело группы ([ChatGroupSeat.tsx](../../packages/client/ui-chat/src/client/chat/ChatGroupSeat.tsx)) обёрнуто в оболочку: фон `--dsw-alias-markdown-code-block`, hairline 0.5px `--dsw-alias-border-l1`, радиус `--dsw-radius-lg` (роль grouped content). Оболочка — всегда смонтированный presentational div внутри `div[data-chat-group-key]` вокруг тела, вне `[data-step-process-content]`; без роли и aria-label, без overflow/contain/transform; тело остаётся единственным scrollport, fade-маски остаются на теле. Переключение раскрытия меняет только материал оболочки классом, не монтаж: участники не перемонтируются, disclosure-состояния и якоря позиции сохраняются, высота строки заголовка не скачет под fold-часами; визуальный инсет живёт внутри scrollport, поверхность переключается без влияния на layout. Заголовок группы — plain-строка над контейнером: в состояниях с заголовком (Compact/Standard в обоих состояниях, Detailed historical) он стоит над оболочкой, в headerless-состояниях (Verbose, Detailed running, Detailed latest completed при On next message) контейнер без заголовка; свёрнутая группа — plain-строка заголовка с выключенной поверхностью оболочки. Reasoning и context-injection входят в контейнер как члены группы; раскрытые тела инструментов и ToolCallTree не меняются. Независимые корни (turn-trigger notice, turn-error, turn-max-tokens, turn-tail, model-retry) остаются вне контейнера и сохраняют текущее оформление; model-retry разрезает контейнер надвое. Running-статус хода (whale) остаётся вне контейнера. Носитель: компонентные спеки материала оболочки по режимам и состояниям + критерий сохранения участников при переключении + живая проба.
2. **Карточка финального ответа.** Карточку получает реплика, удовлетворяющая предикату финала: `turn.status === 'closed'`, `turn-tail.closing.finalNode.seq === data.finalNode.seq` ([turn-tail.ts](../../packages/client/ui-chat/src/client/conversation-nodes/turn-tail.ts), предикат уже вычисляется в [AssistantNodeView.tsx](../../packages/client/ui-chat/src/client/chat/AssistantNodeView.tsx)), только response-место (`groupPart !== 'reasoning'`), только `turn/end.reason === 'completed'`. Предикат не зависит от режима и партиального хвоста без turn/start. Края без карточки: открытый ход; закрытие без closing text-реплики; image-only финал; stopped/failed/interrupted/max-tokens. Карточка — существующая приподнятая нейтральная семья (прецедент QuestionComposer/PlanReviewPanel): фон `--dsw-specific-input-major`, радиус `--dsw-radius-xl` (роль independent content card), `border: 0`, hairline через `--dsw-elevation-panel`. Подпись «Окончательный ответ» / «Final answer» — новый ключ (например `message.finalAnswer`) во всех 8 словарях ui-chat; ключ `settings.foldedReplies.final` в транскрипте не потребляется, термин с ним согласован. Промежуточные реплики остаются plain; во время открытого хода карточки нет; при свёрнутом процессе карточка финала сохраняется. Носитель: компонентные спеки предиката и краёв + обновлённые replay-expected (подпись — видимый текст в ARIA-снимке).
3. **Живой список дел.** [TodoPanel.tsx](../../packages/client/ui-conversation/src/client/skeleton/TodoPanel.tsx) раскрыт, пока сессия работает: сигнал `session.running` берётся из owner-пропсов `InputZone.session` (новый канал/хук не создаётся); триггер — состояние (непустая todo-проекция + running), а не только событие изменения, поэтому уже существующий план тоже раскрывает dock; ручное сворачивание оператором подавляет авто-раскрытие до ухода сессии в idle; при idle dock сворачивается в полосу. Полоса получает прогресс-бар done/total (`aria-hidden`, новые ключи не нужны) рядом с существующими текстовыми счётчиками `todo.progress.*`; StateDot остаётся на раскрытых строках списка, которые сохраняют существующий cap 180px со скроллом. Носитель: обновлённые спеки todo-panel (running через owner-пропсы) + replay-сценарий queue-actions (todo/write в живом ходе) + живая проба.
4. **Охват.** Иерархия действует везде, где видно тело группы процесса: Verbose, Detailed running, раскрытые группы Compact/Standard/Detailed. Таблица режимов, правила группировки, whole-Turn folding и scroll ownership не меняются: видимость ортогональна новой иерархии. Носитель: спеки режимов + replay-сценарии collapse-timing и subagent-conversation.
5. **Доказательства.** `pnpm run test:gui` зелёный. Дешёвая итерация: `build:artifacts` + `test:web:built` с фильтром сценария для обнаружения диффов; полный `DSH_SNAPSHOT=replay pnpm run test:web` (полная сборка + сериальная браузерная сюита) — финальный зелёный гейт; порядок detect → refresh → повторный зелёный прогон. Сценарии с областью транскрипта: collapse-timing (`[data-chat-flow]`), deepseek-messages-chat (centerCol), subagent-conversation (включая `ui-expanded.expected.md`), queue-actions (dock); tool-details — охранник неизменности карточек инструментов (его снимок захватывает только карточки). Масштаб churn измерен: ≳40 сценариев, ~93 expected-файла в snapshots/web и ~106 в apps/web/tests/expected содержат реплики закрытых ходов. Механический критерий refresh: в diff expected допустима только новая строка подписи финала (плюс строки прогресс-полосы в queue-actions/layout.expected.md); любой иной diff блокирует refresh; оболочка без роли/label в ARIA-снимок не попадает. Живая проба обеих тем и узкой ширины на собранном бандле, включая сравнение карточки финала с соседними приподнятыми/утопленными поверхностями (тёмная тема: разделение при фоне страницы). GIF для PR; ревью дизайнера/продукта по dsh-client-ui-ux, в форке — приёмка оператором через fallback скилла «When no approver holds that role».
6. **Документация.** README ui-chat (Grouped rendering, Turn Process Folding), [conversation-nodes README](../../packages/client/ui-chat/src/client/conversation-nodes/README.md) и README ui-conversation описывают новую презентацию; JSDoc затронутых компонентов обновлён в том же изменении. Носитель: `pnpm run test:docs` без новых падений.

## Рамки

Новых настроек нет: иерархия включена всюду, где видно тело группы. Session-события, группировка, сворачивание, таблица режимов и scroll ownership не меняются. Пузырь пользователя не меняется. Раскрытые тела инструментов, ToolCallTree и per-tool views не меняются. Host-пакеты и новые проекции не создаются: dock использует существующий owner-пропс `InputZone.session`. Продуктовый текст — только через typed-словари и `t`; цвета — только семантические токены, без литералов; font weight ≤500 в feature CSS. Правки живут в ui-chat (оболочка группы, карточка финала), ui-conversation (TodoDock) и locale-словарях; новые пакеты не создаются. Рёбра нарезки: locale-ключ и карточка финала — один тикет; каждый UI-тикет обновляет только свои компонентные спеки; replay-refresh — отдельный блокирующий тикет после обоих UI-пунктов.

## Ограничения

Контраст tertiary-текста строк процесса на фоне `markdown-code-block` проверяется живой пробой в обеих темах и является критерием приёмки пункта 1. Контейнер и вложенные код-блоки/ioCard делят токен `markdown-code-block`: заливка вложенных карточек не контрастирует с контейнером, но их hairline-контуры сохраняются — контуры и контраст проверяются живой пробой; двойные соседние рамки не допускаются, паддинг контейнера разводит кромки. Оболочка и карточка не задают overflow/contain/transform: sticky-баннеры код-блоков и breakout широких таблиц сохраняют свои референсы. Capped-тело группы (`min(400px, 50vh)`) скроллится внутри оболочки; fade-маски применяются к телу, не к оболочке. Карточка финала появляется только при закрытом ходе с reason completed: во время работы последняя реплика не маркируется, чтобы метка не мигала «финал → не финал». Snapshot-expected обновляются только после подтверждения намеренного изменения вывода по механическому критерию пункта 5. Изменение user-perceivable: GIF и дизайн-ревью обязательны по правилам клиента; без них работа не принимается.

## Контекст

Текущее состояние: все строки процесса — один стиль (tertiary в покое, 13px, 24px-строка, 4px между строками), цвет общий для всех категорий ([ToolRow.module.css](../../packages/client/ui-tool/src/client/tool/components/ToolRow.module.css), [README ui-chat](../../packages/client/ui-chat/README.md)); тело группы не имеет ни фона, ни рамки ([ChatGroupSeat.module.css](../../packages/client/ui-chat/src/client/chat/ChatGroupSeat.module.css)); реплики — plain markdown полного веса с отступом 12px, промежуточная и финальная визуально идентичны ([AssistantMarkdown.module.css](../../packages/client/ui-chat/src/client/chat/AssistantMarkdown.module.css)). `data.finalNode` есть у каждой settled-реплики ([assistant.ts](../../packages/client/ui-chat/src/client/conversation-nodes/assistant.ts)), поэтому сам по себе не является признаком финала; финал хода определяет `turn-tail.closing` (последняя finalized text-реплика) и `turn-process.latestAnswer` (последний шаг с reply-контентом без tool-call); предикат карточки взят из `turn-tail.closing`, уже вычисляемого в AssistantNodeView, так как путь через `turnProcess` зависит от `foldCompletedTurns` и не работает в Verbose. Полоса «Дела …» над композером — существующий TodoDock (`conversation.input.dock`, order 0), свёрнут по умолчанию (`useState(true)`), счётчики tertiary; owner-пропсы `InputZone` несут `session: SessionSnapshot` с `running: boolean`, точная граница хода клиенту недоступна (`turnBoundary` host-only), queued-ввод переживает границу хода без смены running. Группировка едина для всех четырёх режимов; наличие заголовка зависит от состояния (Detailed running и отложенный Detailed — headerless). Материалы: `markdown-code-block` — recessed-тинт код-блоков и turn-trigger уведомлений; приподнятая семья карточек — `specific-input-major` + `radius-xl` + elevation-panel + border:0 (QuestionComposer/PlanReviewPanel); роль independent content card — R20, grouped content — R16 ([ui-radius.md](../ui-radius.md)); нейтральные рамки — 0.5px ([web-styling.md](../web-styling.md)). omp (oh-my-pi) решает иерархию степенью контейнеризации: tool-карточки в рамке с lifecycle-цветом (успех намеренно нейтральный), проза агента plain полного веса, thinking курсивом и свёрнут, пользователь — залитый пузырь; финальный ответ omp не выделяет — карточка финала является расширением поверх omp по требованию оператора ([tool-execution.ts](https://github.com/can1357/oh-my-pi/blob/main/packages/tui/src/chat/tool-execution.ts), [assistant-message.ts](https://github.com/can1357/oh-my-pi/blob/main/packages/tui/src/chat/assistant-message.ts), [thinking-display.ts](https://github.com/can1357/oh-my-pi/blob/main/packages/tui/src/chat/thinking-display.ts)). Режим на скриншоте оператора точно не определён (видны и заголовки групп, и плоские строки); охват «везде, где видно тело группы» закрывает эту неопределённость.

## Демо-путь

Собрать бандлы затронутых пакетов (`pnpm --filter @deepseek-ai/dsh-client-ui-chat bundle` и ui-conversation) либо держать `pnpm run dev:web`, обновить страницу GUI. Открыть живую многоагентную сессию: в Verbose и в Standard с раскрытой группой тела групп процесса лежат в тихих контейнерах, заголовки и реплики — на чистом фоне; завершённый ход (reason completed) показывает финал в карточке с подписью; пока сессия работает, TodoDock раскрыт и показывает живой список, при уходе в idle сворачивается в полосу с прогрессом. Повторить в светлой и тёмной темах и на узкой ширине; снять GIF для PR. Replay-сценарии — доказательство пункта 5, не шаг демо: replay является e2e-полосой сравнения expected, а не страницей GUI.
